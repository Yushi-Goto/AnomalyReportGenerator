# 概要
このチケット及び対応ブランチでは、[システム概要](https://github.com/Yushi-Goto/AnomalyReportGenerator/wiki/%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E6%A6%82%E8%A6%81#%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E6%A7%8B%E6%88%90%E3%82%A2%E3%83%BC%E3%82%AD%E3%83%86%E3%82%AF%E3%83%81%E3%83%A3)の「異常検知」部分（コンポーネント）を開発する。
具体的には以下のAPIエンドポイントを実装する。
- /anomaly/predict
- /anomaly/heatmap

# コンポーネントの入出力
- 入力
    - 推論対象の画像
- 出力
    - InferenceOutputデータクラス
        - pred_label: 正常(`0`), 異常(`1`)
        - pred_score: 異常スコア(float値)
        - threshold: 異常とみなす閾値(float値)
        - extra
            - anomaly_map: 異常マップの有無(ある場合は`<available>`が含まれる)
            - pred_mask: 異常マスクの有無(ある場合は`<available>`が含まれる)
        - request_id: リクエストのID(UUID4)
    - ヒートマップ画像(PNGバイトデータのストリーミング)

# APIエンドポイント
## APIエンドポイント一覧
| エンドポイント   | 入力                                                                                                                                                       | 出力                            | 
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | 
| /anomaly/predict | file: 推論対象の画像                                                                                                                                       | PredictResponseクラス: pred_label, pred_score, threshold, extra, request_id     | 
| /anomaly/heatmap | request_id: キャッシュ情報参照用のID, overlay: 元の推論対象の画像にオーバーレイするかどうか, normalize: ヒートマップ正規化の有無, file: 元の推論対象の画像 | 異常ヒートマップ画像: PNGバイトデータのストリーミング | 

## 1) `/anomaly/predict`（JSONのみ）の想定用途
■目的
- システム判断（OK/NG、しきい値判定、ログ保存、次工程への分岐）
- 自動処理の基礎データ（ラベル、スコア、閾値、異常マップの有無、異常マスクの有無、リクエストID）

■ユースケース
1. クライアント（検査UI、バッチ、別システム）が画像を送信
2. `/anomaly/predict` が JSONでスコアを返す
3. クライアントは `pred_score >= threshold` のように判定して
    - OKなら保存だけして終了
    - NGなら 人の確認ステップへ遷移（次の `/anomaly/heatmap` や GPT説明へ）

■要点
- 常に呼ばれる**主ルート**になる（と思う）
- レスポンスが小さく、処理も軽く、ログ/DBにも保存しやすい

## 2) `/anomaly/heatmap`（PNGのみ）の想定用途
■目的
- 人が原因を理解するための可視化
- 誤検知・見逃し・照明影響などの デバッグ
- “このモデルはここを見ている” を確認して現場説明に使う

■ユースケース
`/anomaly/predict` の**結果が怪しいときだけ分岐先として呼ばれる**。
- 例：UIでサムネ一覧表示 → NGだけ「ヒートマップを表示」
    1. `/anomaly/predict` で NG と判定
    2. 画面に「ヒートマップ表示」ボタンを出す / 自動で取得
    3. `/anomaly/heatmap?overlay=1&normalize=1` で PNG取得
    4. 元画像の上に重畳表示して、オペレータが目視確認

# システム全体のフロー
### ステップA：一次判定（自動）
`/anomaly/predict` → スコアで OK/NG

（ここで、次ステップでヒートマップ画像作成のために「推論結果」「リサイズした元画像」「異常マップ画像」をTTLキャッシュとして保存しておく）

### ステップB：根拠提示（人の確認）
NGや保留のときだけ `/anomaly/heatmap` → 可視化で「どこが異常か」

### ステップC：説明（文章化・報告書化）
`gpt/explain` → 入力：(predict のスコア/ラベル +) 元画像＋ヒートマップ重畳＋パッチ、出力：現場向け所見、確認ポイント、誤検知の可能性
